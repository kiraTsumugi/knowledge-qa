# 05 · 复盘

## 最难的问题

**1. 冲突的"该报"与"不该报"，边界全在检索质量上。**
同一个 `报销期限`，泛化问法该报冲突、带"出差"限定的问法该作答 D01。最初检索用简单词重叠计分，
两种问法结果混乱：先是追问场景误报冲突（「期限」通用词误召回），提高阈值后又变成"出差"问法漏报
D01 的存在。最终方案是 **unique-token 优先 + IDF 加权 + 相对阈值**：只在单一文档出现的词
（"出差"）是强信号，命中即锁定；否则按权重阈值过滤。**检索质量决定了模型能看到什么事实，
模型决策再正确，看到的事实错了也白搭。**

**2. 差点把正确行为"改坏"。**
修完追问误报后，测试显示"出差报销要多久"从"冲突"变成了"已作答"，第一反应是回归 bug。
核对参考实例后发现：**有场景限定时依据 D01 作答正是题目规定的正确行为**——该改的是测试期望，
不是代码。教训：改 bug 前先确认"什么是正确"，否则会朝着错误目标修。

**3. 工具失败的死循环。**
失败返回没有 `hits` 字段，Mock 的收集逻辑识别不到"这是一次失败的检索"，于是无限重试。
根因在事实收集的字段约定——修复方式是让收集逻辑按 `tool` 字段识别（失败返回也带 `tool`）。

## 学习收获

- **引用安全要硬校验，不能靠 prompt 自律**："answered 必须带 quotes"写进循环层，
  模型试图无引用作答直接被拦截。结构保证 > 提示词祈祷。
- **冲突处理的价值在"不做什么"**：不选边、不编造、不无依据作答。输出空答案+双方原文+
  请求确认，比给出一个"看起来对"的答案更有价值。
- **数据驱动检索改进**：同义词表、IDF、阈值都是数据/参数，改词表即扩展召回，
  不需要改代码。

   模型据优先级裁决——仍由数据决定，不硬编码。
