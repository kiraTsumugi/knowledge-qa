# 01 · 需求

## 用户与目标

**用户**：企业员工。
**目标**：快速找到制度/产品问题的**可靠答案** —— 答案必须有依据（引用文档 ID 与原文片段），
有冲突时如实呈现，无资料时明确缺口。

**非目标**：真实工单流转、多轮会话持久化、权限分级。

## 范围

| 做 | 不做 |
|---|---|
| 文档检索 / 片段读取 | 向量检索（先用关键词+IDF 加权+同义词）|
| 引用溯源（文档 ID + 原文） | 真实模型微调 |
| 冲突检测与请求确认 | 多轮会话持久化 |
| 资料外问题拒答 | UI / 部署 |
| 上下文追问改写 | 权限/审计 |

## 输入

- **问题** + 可选对话历史
- 合成制度文档库（`data/docs.json`，含文档 ID/版本日期/条款）
- 同义词表（`data/synonyms.json`，供改写问法归一化）

## 成功标准（对应考核验收点）

| # | 成功标准 | 判据 |
|---|---|---|
| S1 | 明确答案 | `answered` + 引用原文支持答案 |
| S2 | 文档冲突 | D01(30天) vs D02(15天) → `needs_clarification` + 列冲突，不选边 |
| S3 | 资料外问题 | `not_found` + 缺口，不编造 |
| S4 | 改写相似问题 | 同义词归一化后命中同一文档 |
| S5 | 上下文追问 | 结合历史补全检索词后再检索 |
| S6 | 工具失败 | `tool_error`，明确失败 |
| S7 | ReAct 决策 | 模型据检索事实调整动作，≥2 条不同路径 |
| S8 | 步数上限 | 超限 `incomplete` |
| S9 | 引用安全 | 无引用不输出答案；引用必须来自原文 |
| S10 | 数据可替换 | 换文档内容 → 答案/动作随之改变 |

## 交付结果字段

`回答` / `引用（文档 ID + 原文片段）` / `资料缺口` / `任务状态`。
